# Накопления и цели

Раздел `/savings` и кнопка «🌱 Накопления» работают в выбранном личном или семейном бюджете. Старые кнопки «🎯 Цель» и «🧭 Распределение» открывают новый раздел, в том числе из ранее отправленной Telegram-клавиатуры.

## Цели

Пять шагов: название, сумма, уже выделенные деньги, срок, выбранный ежемесячный взнос. Подтверждение сохраняет план. Можно изменить все поля, заменить отмеченную сумму или отправить цель в архив. Старые цели сохраняются; если срок раньше не был задан, бот предлагает его уточнить.

Срок задается числом месяцев (1–600) или месяцем ММ.ГГГГ. В расчет включены текущий и целевой месяцы, дата цели — конец целевого месяца. Необходимый взнос: оставшаяся сумма / число взносов, с округлением вверх до копейки. При взносе 0 срок по выбранному взносу не вычисляется. Просроченная цель явно помечена. Достигнутые и архивные цели не уменьшают возможности месячного плана.

Расчет не включает доходность или изменение цены цели. Пользователь сам выбирает размер взноса и место накоплений. Ввод накоплений не переводит деньги и не создает расходов/доходов. Одни деньги нельзя одновременно относить к разным целям или резерву.

## Резерв и месячный план

Период резерва задается пользователем (1–36 месяцев); 3–6 месяцев необходимых расходов объясняются как распространенный ориентир, не норма для всех. Размер = необходимые месячные расходы × выбранный период. Уже накопленная сумма и ежемесячный взнос задаются отдельно.

Для оценки возможностей пользователь подтверждает пять сумм: доход после налогов, все обычные расходы с платежами по долгам, отдельные отчисления на известные нерегулярные траты, другие накопления вне раздела и нераспределенный запас. Неполученные премии не считаются гарантированным доходом. План не подставляется автоматически из нескольких операций в журнале.

Из дохода вычитаются четыре группы отчислений; затем отдельно вычитаются выбранные взносы в незавершенные цели и резерв. Отрицательная разница показывается явно. Никаких автоматических 10/20/50 процентов. Это месячный план, а не текущий банковский баланс: даты поступлений и платежей пользователь сверяет отдельно. План старше 31 дня отмечается как требующий сверки.

## Обновление бота

Railway подключен к GitHub `main`; опубликованный коммит автоматически разворачивается. Сервис использует одну polling-replica и постоянную SQLite-базу `/app/data/finance.db`. Не запускать второй экземпляр с тем же Telegram token.

При следующем обращении авторизованного пользователя бот обновляет старую reply-клавиатуру. `/start` повторять не требуется. Во время активной формы обновление меню откладывается, чтобы сохранить клавиатуру отмены. Отметка версии хранится в базе, массовой рассылки при старте нет.

FSM хранится в SQLite с разделением bot/chat/user/thread/business connection/destiny. Черновики живут 30 дней после последнего изменения; сохраненные планы и операции не удаляются по этому сроку. Поврежденная запись FSM сбрасывается целиком без вывода содержимого в журнал.

Процесс при развертывании заменяется автоматически; с прикрепленным volume возможна короткая пауза. Активные обработчики ожидаются до 20 секунд до закрытия FSM; на Railway заданы `RAILWAY_DEPLOYMENT_DRAINING_SECONDS=30` и `RAILWAY_DEPLOYMENT_OVERLAP_SECONDS=0`. Это не обещание нулевого простоя или доставки каждого сообщения ровно один раз при аварии. Подтверждения целей идемпотентны; изменения планов защищены версиями.

При первом переходе со старого MemoryStorage уже находившиеся в памяти незавершенные формы восстановить невозможно. Все последующие версии используют постоянное хранилище. Перед расширением старой схемы целей создается SQLite backup в `data/backups`; миграции добавляют поля без удаления прежних записей.

Для Docker Compose на собственном сервере автоматический GitHub deploy не настроен: образ требуется собирать отдельно. Пользовательская клавиатура и SQLite FSM обновляются одинаково в обоих вариантах.
