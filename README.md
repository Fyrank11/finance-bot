# Finance Bot

Учёт личного и семейного бюджета в Telegram: быстрый ввод с iPhone, лимиты, обязательные платежи, понятный остаток и выгрузка Excel. Интерфейс на русском, суммы в рублях, даты по умолчанию по Москве.

Версия с новыми функциями — ветка `codex/budget-assistant`. Сравнение Monefy, CoinKeeper и Дзен-мани, выбранные функции и ограничения описаны в [docs/FEATURES.md](docs/FEATURES.md).

## Первые шаги

1. Откройте **личный чат** с запущенным ботом и отправьте `/start`.
2. В «Настройки → Начальные деньги» укажите сумму, которая была **перед первой записанной операцией**. По умолчанию это 0. Текущий банковский баланс поверх старых операций вводить не нужно.
3. Нажмите «Доход» или «Расход» либо отправьте запись обычным сообщением:

   ```text
   кофе 350 рублей
   + зарплата 150000
   такси 1,5к вчера
   продукты 2 450; супермаркет #дом
   ```

4. Проверьте карточку и подтвердите запись. До сохранения можно изменить сумму, тип, категорию, дату и комментарий. В истории доступны исправление и удаление с подтверждением.
5. Откройте «Мой бюджет»: здесь доходы, расходы и расчётный остаток. Выбранный месяц используется также для истории, лимитов и Excel.
6. В «Лимиты» задайте план по категориям на месяц. Ноль означает «не тратить», слово `убрать` удаляет лимит.

Одна строка — одна операция. `к` и `тыс` означают тысячи, `млн` — миллионы. Без знака известные категории доходов считаются доходом, остальные — расходом; тип виден перед сохранением. Комментарии и `#метки` пишите после `;`. Для другой даты используйте кнопку «Дата»; будущие фактические операции не принимаются.

Диктовка **клавиатурой iPhone** подходит: бот получает обычный текст. Голосовые сообщения, чеки и скриншоты автоматически не распознаются.

## Полезные разделы

| Команда или раздел | Что делает |
|---|---|
| `/payments` — обязательные платежи | Ежемесячные платежи с суммой и днём оплаты. Кнопка «Оплачено» и подтверждение создают расход; до этого платёж остаётся планом. Фоновых напоминаний нет. |
| `/analytics` — аналитика | Сравнение расходов с таким же количеством первых дней предыдущего месяца. Топ категорий находится в «Мой бюджет». |
| `/search` — поиск | Поиск операций по всем месяцам по категории, комментарию или `#метке`; например `/search #дом`. |
| `/family` — семья | Общий бюджет по приглашению, до 5 участников. Личный бюджет хранится отдельно; можно переключаться между ним и общим. |
| «Скачать Excel» | Файл `.xlsx` с обзором, операциями и лимитами выбранного месяца. Изменения файла обратно в бот не загружаются. |
| «Ещё» | Долги, цели накоплений и прежние вспомогательные расчёты. |
| `/help`, `/menu`, `/cancel` | Справка, главное меню и отмена ввода. |
| `/whoami` | Ваш Telegram ID для настройки доступа; финансовые данные не показывает. |

В общем бюджете виден автор операции; все участники могут просматривать и менять общие записи. Владелец создаёт одноразовый код и передаёт его приглашённому. Тот открывает `/family` → «Ввести код приглашения» и подтверждает вступление. Приглашённый участник может выйти, владелец — исключить участника. Для доступа к боту Telegram ID каждого участника должен быть разрешён в настройках запуска. Переключение бюджета не переносит личную историю в семейную.

В обзоре текущего месяца остаток после обязательств вычитает из расчётного остатка ещё не оплаченные платежи до конца месяца, включая просроченные. Дневной ориентир распределяет положительный остаток по оставшимся дням, включая сегодня. Это расчёт **по внесённым данным**, а не проверенный остаток на банковских счетах. Не внесённые траты, будущая зарплата, не заданные обязательства и резерв на цели в него не попадут.

Перевод между своими счетами и снятие наличных не записывайте как доход или расход. Покупку по кредитке и погашение той же суммы нельзя учитывать как два расхода. Отдельные записи о долгах и целях сами по себе не изменяют денежный остаток.

## Запуск

Нужен сервер или постоянно включённый компьютер с Docker и Docker Compose. Репозиторий на GitHub сам по себе не запускает бота. Подписки на Monefy, CoinKeeper и Дзен-мани не нужны; расходы на сервер зависят от выбранного хостинга.

Для первой установки скачайте подготовленную версию:

```bash
git clone --branch codex/budget-assistant https://github.com/Fyrank11/finance-bot.git
cd finance-bot
```

1. Создайте бота через [BotFather](https://t.me/BotFather), если его ещё нет.
2. В каталоге проекта создайте настройки:

   ```bash
   cp .env.example .env
   ```

3. Откройте `.env` в редакторе сервера и задайте `BOT_TOKEN`. Настоящий токен храните **только в `.env` или секретах хостинга**. Не отправляйте его в чат и не добавляйте в GitHub.
4. Первый запуск:

   ```bash
   docker compose up -d --build
   ```

5. Отправьте боту `/whoami`. Впишите полученный ID в `ALLOWED_USER_IDS` в `.env`. Если участников несколько — перечислите ID через запятую. С пустым списком бот показывает ID и подсказку запуска, но не предоставляет доступ к бюджету.
6. Примените настройки:

   ```bash
   docker compose up -d --force-recreate
   ```

7. Откройте `/start` и внесите первую операцию. Для проверки работы контейнера используйте `docker compose logs --tail=50 bot`.

По умолчанию база хранится в `data/finance.db`: папка `data` подключена к контейнеру и сохраняется при пересоздании контейнера. Если меняете `DB_PATH`, путь должен оставаться внутри постоянного тома. Для одного токена запускайте **один процесс** бота. В группах бюджет недоступен. Проверка доступа применяется и к сообщениям, и к кнопкам.

После перезапуска незавершённый черновик нужно ввести заново; сохранённые записи остаются в SQLite.

Без Docker нужен Python 3.12:

```bash
python -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
python -m app.bot
```

## Обновление и резервная копия

При первом запуске этой версии поверх старой базы бот сам сохраняет проверенную копию через SQLite Backup API **до миграции**. Это происходит, если в таблице `transactions` ещё нет поля `amount_minor` или `version`. Копия получает уникальное имя `backups/finance-before-upgrade-*.db` рядом с файлом базы; в журнал выводится только её путь. Если копирование или проверка не удались, запуск прекращается без миграции. Для новой базы и уже обновлённой схемы копирование пропускается.

Автоматическая копия находится на том же томе: она помогает откатить это обновление, но не заменяет резервную копию вне сервера на случай потери тома. В Railway путь `DB_PATH` и соседняя папка `backups` должны находиться внутри постоянного тома.

Перед обновлением остановите бот и сохраните базу **вне каталога репозитория**. Пример для стандартного пути:

```bash
docker compose stop bot
cp data/finance.db ../finance-bot-before-update.db
git pull --ff-only
docker compose up -d --build
```

Каждой новой копии задавайте отдельное имя, чтобы не перезаписать предыдущую. Если базы ещё нет, копирование пропустите. Не копируйте работающую SQLite-базу простым `cp`: для копирования без остановки нужен SQLite Backup API или команда `.backup` клиента SQLite. Не публикуйте базу, резервные копии и `.env` в GitHub.

Обновляйте текущую ветку `codex/budget-assistant`. Если есть собственные незакоммиченные изменения, сохраните их до `git pull`; не используйте принудительный сброс. Миграции добавляют нужные таблицы и поля, сохраняя прежние операции, долги и цели. Для отката нужны резервная копия базы и соответствующая ей версия кода; восстанавливайте их при остановленном боте.

## Проверка без Telegram

```bash
pip install -r requirements-dev.txt
pytest -q
```

Автоматические проверки выполняются без настоящего Telegram-токена. После установки отдельно проверьте ввод, подтверждение, исправление и Excel в личном чате.

Для подготовленной версии пройдены 109 тестов: расчёты в копейках, миграция старой базы, диалоги Telegram, двойная оплата, приглашения, отзыв доступа, устаревшие кнопки и конфликтующие исправления. Проверка живого подключения Telegram и сборка Docker в этой среде не выполнялись.
